公司内网编译、运行与配置指南

本指南说明如何在公司内网环境（HTTP 代理 + MITM 证书拦截 + 内网 npm 仓库）下编译、运行 MyDSH，并配置网络与 LLM 网关。同时说明这些修改如何保证不影响可直连互联网的环境。

MyDSH 是 DeepSeek Harness 的一个 fork（本仓库），做了以下定制：

  • 数据目录隔离：~/.dsh → ~/.mydsh，与官方版完全互不干扰
  • 品牌改名：UI 显示 “MyDSH / MyDSH 本地构建”，安装包名 mydsh-*.exe，应用名 MyDSH
  • 免登录：默认禁用 DeepSeek 账号登录，改用自建 OpenAI 兼容 LLM 网关
  • 网络自适应：通过 ~/.mydsh/network.json 可选注入公司代理与 MITM CA 证书；文件不存在时零注入，直连环境行为不变

1. 网络环境

用途地址
HTTP/HTTPS 代理http://proxy-rd.td-tech.com:8080
git SSH 代理127.0.0.1:18080（见下方 git 配置）
内网 npm 仓库http://repo.rd.td-tech.com/repo/api/npm/npm-virtual/

公司网络对 HTTPS 做透明拦截（伪造证书链），Node.js 默认不信任该证书，因此构建与运行时需要：

  • NODE_EXTRA_CA_CERTS 指向 MITM CA 证书（本仓库已将其打包进安装包 resources/mitm-ca.pem，来源为 apps/desktop/resources/mitm-ca.pem）
  • NODE_USE_ENV_PROXY=1 让 Node 的 fetch 走环境变量代理

git 网络配置

git 经 SSH + ProxyCommand 走本地代理（与 D:\shaopx\myagent 相同的配置），~/.ssh/config：

Host github.com
  HostName github.com
  User git
  ProxyCommand connect -H 127.0.0.1:18080 %h %p

克隆：git clone git@github.com:shaopx/mydsh.git

2. 编译（公司内网）

2.1 环境要求

  • Node.js ≥ 24.9
  • pnpm（corepack enable 或自行安装）
  • Windows 打包需要 NSIS（electron-builder 会自动下载，经代理）

2.2 构建终端环境变量（PowerShell）

$env:HTTP_PROXY = 'http://proxy-rd.td-tech.com:8080'
$env:HTTPS_PROXY = 'http://proxy-rd.td-tech.com:8080'
$env:NO_PROXY = 'localhost,127.0.0.1,repo.rd.td-tech.com'
$env:NODE_USE_ENV_PROXY = '1'
$env:NODE_TLS_REJECT_UNAUTHORIZED = '0'   # 仅供构建进程下载 Electron/NSIS 使用
$env:DSH_DESKTOP_NPM_REGISTRY = 'http://repo.rd.td-tech.com/repo/api/npm/npm-virtual/'

说明：

  • NODE_TLS_REJECT_UNAUTHORIZED=0 仅用于构建期下载（Electron 二进制、NSIS 等经代理时的自签证书问题）。运行期不需要它，运行期用打包内的 CA 证书。
  • DSH_DESKTOP_NPM_REGISTRY 指向内网 HTTP 仓库。apps/desktop/scripts/desktop-release-environment.mjs 已修改为允许 http: 协议与带路径的 registry（上游只允许 HTTPS），这是内网构建所必需的。
  • 内网 registry 必须加入 NO_PROXY，否则走代理反而失败。

2.3 本机打包配置 apps/desktop/.env.windows

该文件被 Git 忽略（不入库），需按需创建：

DSH_DESKTOP_APP_ID=com.mydsh.desktop

其余更新源字段仅签名/自动更新时需要；本地未签名构建可全部留空（参考 apps/desktop/.env.windows.example）。

2.4 编译命令

pnpm install
pnpm run build                     # build:artifacts + build:check
pnpm run package:desktop:win:x64:unsigned

产物：apps/desktop/.desktop-build/targets/win-x64/unsigned-artifacts/mydsh-<version>-win-x64-unsigned.exe

耗时提示：完整安装包管线每次都会全量构建 70+ 个包、装配运行时、跑打包自检（CLI、Office 技能等）并做 NSIS 压缩（324MB），全程十几分钟属正常。日常迭代可用 pnpm --dir apps/desktop run package:win:x64:dir 产出免安装的 win-unpacked\MyDSH.exe（跳过 NSIS，快很多），或直接 pnpm dsh web dev 运行。

安装后开始菜单/进程名为 MyDSH。与官方 DeepSeek Harness 可同时运行、互不干扰：

Electron userData%APPDATA%\@deepseek-ai\dsh-desktop%APPDATA%\MyDSH
安装目录...\Programs\dsh-desktop...\Programs\MyDSH
应用 ID官方 IDcom.mydsh.desktop

数据目录由 packages/util/home-paths/src/index.ts 的 DSH_HOME_DIR_NAME = '.mydsh' 决定；仍可用 DSH_HOME 环境变量整体覆盖。

4. 网络配置（运行时）

运行时网络行为由 ~/.mydsh/network.json 驱动（apps/desktop/src/node-environment.ts）：

{
  "httpProxy": "http://proxy-rd.td-tech.com:8080",
  "httpsProxy": "http://proxy-rd.td-tech.com:8080",
  "noProxy": "localhost,127.0.0.1",
  "extraCaCerts": "packaged"
}

字段说明：

  • httpProxy / httpsProxy：代理地址。设置任一即自动启用 NODE_USE_ENV_PROXY=1
  • noProxy：不走代理的主机列表
  • extraCaCerts："packaged" 选用安装包内置的 resources/mitm-ca.pem（公司 MITM CA），也可填本机 PEM 文件绝对路径

规则（保证不影响直连环境）：

  • 文件不存在 → 不注入任何变量，直连互联网环境行为与上游完全一致
  • 文件损坏 → 警告并跳过注入，不启动错误配置的 Host
  • 调用方显式传入的环境变量始终优先于 network.json 默认值

注意："packaged" 只在安装包内解析（process.resourcesPath）；从源码 dev 运行（如 pnpm dsh web）时会警告并跳过 CA 注入。dev 模式如需内网 LLM，可将 extraCaCerts 改为本机 PEM 绝对路径（如 d:\code\mydsh\apps\desktop\resources\mitm-ca.pem），或临时设 NODE_EXTRA_CA_CERTS。

6. 直连互联网环境的兼容性

所有内网相关修改均为“配置驱动”或“品牌级”，不含任何硬编码的公司地址：

  • network.json 不存在时 desktopNodeEnvironment 零注入（见第 4 节规则）
  • DSH_DESKTOP_NPM_REGISTRY 未设置时使用默认 registry；desktop-release-environment.mjs 只放宽了校验（允许 http/带路径），不改变默认值
  • mitm-ca.pem 仅在 network.json 声明 extraCaCerts: "packaged" 时才被引用
  • 品牌改名（MyDSH、.mydsh、productName、appId）对所有环境一致生效，但均为独立命名，不与官方版冲突

因此直连互联网的环境按上游标准流程（pnpm install && pnpm run build）即可编译运行，无需任何额外配置。
